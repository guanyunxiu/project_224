## 1. 产品概述

线性审批流系统是一套可视化的工作流管理平台，支持通过拖拽式画布设计审批流程，并提供完整的运行时审批能力。目标用户为需要审批流程管理的企业团队，解决传统审批流程配置困难、缺少可视化设计、审批过程不透明等问题。

## 2. 核心功能

### 2.1 用户角色

| 角色 | 说明 | 核心权限 |
|------|------|----------|
| 流程设计员 | 设计和管理审批流程 | 创建/编辑/发布/删除流程 |
| 审批人 | 参与审批流程的节点负责人 | 同意/驳回申请 |
| 发起人 | 发起审批申请的普通用户 | 发起申请、查看我发起的 |

### 2.2 功能模块

1. **流程设计器**：可视化画布设计审批流程，配置审批节点与审批人
2. **流程管理**：流程列表、保存草稿、发布流程
3. **发起申请**：选择已发布流程，填写表单发起审批
4. **我的待办**：查看和处理待审批任务
5. **我的已办**：查看已处理的审批记录
6. **我发起的**：查看自己发起的申请及状态
7. **审批详情**：审批操作（同意/驳回）及审批历史时间轴

### 2.3 页面详情

| 页面名称 | 模块名称 | 功能描述 |
|----------|----------|----------|
| 流程列表页 | 流程卡片列表 | 展示所有流程（草稿/已发布），支持新建、编辑、删除、发布 |
| 流程设计器页 | VueFlow画布 | 拖拽节点、缩放平移、连线；左侧节点面板（开始/审批人/结束） |
| 流程设计器页 | 节点属性面板 | 选中节点后右侧显示：节点名称、审批人类型（指定用户/指定角色/发起人主管）、审批人选择 |
| 流程设计器页 | 工具栏 | 保存草稿、发布流程、流程校验、撤销/重做 |
| 发起申请页 | 流程选择 | 下拉选择已发布流程 |
| 发起申请页 | 申请表单 | 根据流程动态展示表单：申请标题、申请说明 |
| 我的待办页 | 待办列表 | 展示待审批任务卡片，显示流程名称、发起人、发起时间 |
| 我的已办页 | 已办列表 | 展示已处理的审批记录，显示操作结果（同意/驳回） |
| 我发起的页 | 发起列表 | 展示我发起的申请，显示当前状态（审批中/已通过/已驳回） |

| 审批详情页 | 审批历史时间轴 | 按时间展示每个节点的审批人、操作、意见、时间 |

## 3. 核心流程

### 3.1 流程设计流程

用户进入流程列表 → 新建流程 → 进入设计器画布 → 从左侧拖拽节点到画布 → 配置节点属性 → 连接节点 → 点击校验 → 校验通过后保存/发布

### 3.2 审批运行流程

用户进入发起申请 → 选择已发布流程 → 填写申请表单 → 提交 → 流程按线性顺序流转 → 审批人收到待办 → 审批人同意则流转到下一节点 → 审批人驳回则流程终止 → 流程结束

```mermaid
flowchart TD
    "发起申请" --> "提交表单"
    "提交表单" --> "开始节点"
    "开始节点" --> "审批节点1"
    "审批节点1" -->|"同意"| "审批节点2"
    "审批节点1" -->|"驳回"| "流程终止"
    "审批节点2" -->|"同意"| "结束节点"
    "审批节点2" -->|"驳回"| "流程终止"
    "结束节点" --> "流程完成"
```

### 3.3 流程校验规则

```mermaid
flowchart TD
    "点击校验" --> "检查开始节点"
    "检查开始节点" -->|"有且仅有一个"| "检查结束节点"
    "检查开始节点" -->|"0个或多个"| "报错：必须有一个开始节点"
    "检查结束节点" -->|"有且仅有一个"| "检查连通性"
    "检查结束节点" -->|"0个或多个"| "报错：必须有一个结束节点"
    "检查连通性" -->|"开始可达结束"| "检查环路"
    "检查连通性" -->|"不可达"| "报错：存在孤立节点"
    "检查环路" -->|"无环"| "检查审批节点配置"
    "检查环路" -->|"有环"| "报错：流程不允许有环路"
    "检查审批节点配置" -->|"全部配置审批人"| "校验通过"
    "检查审批节点配置" -->|"存在未配置"| "报错：审批节点必须配置审批人"
```

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：#1677FF（Ant Design蓝），辅助色：#52C41A（成功绿）、#FF4D4F（警告红）
- 按钮风格：圆角按钮，主要操作用实心按钮，次要操作用虚线/文字按钮
- 字体：-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial
- 布局风格：左侧导航栏 + 内容区，卡片式布局
- 图标风格：Ant Design Icons 线性图标

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI元素 |
|----------|----------|--------|
| 流程列表页 | 流程卡片 | 白色卡片、状态标签（草稿/已发布）、操作按钮、搜索栏 |
| 流程设计器页 | 左侧节点面板 | 折叠面板，节点可拖拽，不同类型用不同颜色标识 |
| 流程设计器页 | 中央画布 | 浅灰网格背景、节点圆角矩形、连线贝塞尔曲线、小地图 |
| 流程设计器页 | 右侧属性面板 | 表单式布局，Ant Design表单组件 |
| 流程设计器页 | 顶部工具栏 | 图标按钮组，校验结果用消息提示 |
| 发起申请页 | 表单区 | 居中卡片表单，步骤式引导 |
| 我的待办/已办/发起页 | 列表区 | 表格/卡片列表，标签筛选，分页 |
| 审批详情页 | 时间轴 | Ant Design Timeline，节点状态用不同颜色图标 |

### 4.3 响应式设计

- 桌面优先设计，流程设计器需 1280px 以上宽度获得最佳体验
- 列表页面在 768px 以上正常展示，移动端简化为卡片流
- 审批详情页在移动端保持时间轴纵向布局

## 5. 数据模型

### 5.1 Mock 数据结构

采用 Pinia + localStorage 持久化的纯前端方案，核心数据结构如下：

- **FlowDefinition**（流程定义）：id, name, status(draft/published), nodes[], edges[], createdAt, updatedAt
- **FlowNode**（流程节点）：id, type(start/approver/end), label, position, approverType(user/role/manager), approverIds
- **FlowEdge**（流程连线）：id, source, target
- **Application**（申请实例）：id, flowId, title, description, applicantId, status(pending/approved/rejected), currentNodeId, createdAt
- **ApprovalRecord**（审批记录）：id, applicationId, nodeId, approverId, action(approve/reject), comment, createdAt
